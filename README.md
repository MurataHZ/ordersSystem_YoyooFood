# Yoyoo Food Station

给摆摊使用的双手机订单系统。前端接单，后端按队列制作，销售页统计完成订单与金额。

无需注册、登录、付费服务或第三方依赖。包含可以直接打开的单机测试版，以及电脑运行的局域网同步版。**这两个模式的数据相互独立。**

如果电脑和手机在不同地点，使用新增的 `start-remote-windows.cmd`，按 `远程使用说明.txt` 操作。
这个入口会自动下载 Python 便携包与 Cloudflare 连接工具，生成含随机访问码的临时 HTTPS 链接；手机不需要和电脑连同一个网络。
远程模式只绑定电脑本机端口，通过完整链接访问。网址每次启动会变化，订单仍保存在同一个 `data` 文件夹中。
Cloudflare 将 Quick Tunnel 定位为开发测试用途，不保证在线率；长期营业应再配置固定隧道或正式托管。

## 先看效果：不用安装，不用网络

1. 解压本项目。
2. 在 Windows 电脑双击 `index.html`，用 Chrome、Edge 等正常浏览器打开。
3. 页面右上角显示“本机测试”。进入前端，创建几杯，再试完成、删除、撤销和销售信息。
4. 关闭并重新打开同一个文件，正常情况下记录仍在同一浏览器中。

测试版将记录保存在浏览器的本机存储中。不要在无痕窗口中做正式记录，也不要清除浏览器数据。移动或改名测试文件后，某些浏览器会将它视为另一份存储。

**单机 HTML 文件的记录不会在不同手机之间同步。iPhone 的“文件”预览有时不会运行网页脚本，不要用它判断系统是否可用；手机测试请通过下面的服务器地址，在 Safari 中打开。**

## 两台 iPhone 同步：推荐营业方式

### 电脑准备

电脑需要 Python 3.9 或更新版本。除此之外，不需要安装软件包，不需要运行 `pip install`，也不需要 Node.js。

1. 如果已有 Python，可以直接继续；如果没有，安装 Python 时勾选 **Add python.exe to PATH**。
2. 解压文件到固定目录。不要直接在压缩包里运行。
3. 双击 **`start-windows.cmd`**。
4. 电脑浏览器会打开系统；启动窗口会显示类似：

   ```text
   电脑访问：http://127.0.0.1:8080
   手机访问：http://192.168.1.123:8080
   ```

   这里的手机地址只是示例，**请使用你自己启动窗口打印的地址**。

### 手机连接

1. 两台 iPhone 和电脑连接**同一个 Wi-Fi 或可以互相访问的热点网络**。
2. 两台手机都用 Safari 打开启动窗口中的“手机访问”地址。
3. 第一台进入“前端”，第二台进入“后端”。
4. 在前端创建一笔订单。后端通常在约 1 秒内显示对应中文订单。
5. 在前端点击完成，检查后端消失、销售页增加对应金额。

这个方式不需要互联网，但需要局域网。**电脑必须能被摊位的手机访问：电脑如果留在家里，手机却在别处的摊位，同一个离线方案不能跨地点连接。** 可以把笔记本带到摊位接同一个网络；如果要把电脑留在家里，就需要后续配置联网托管或远程访问。

营业时保持电脑开机、不休眠，启动窗口不要关闭。手机锁屏时不会继续刷新；解锁回到页面后会立即重新连接。iOS 实机和你现场网络还需要用两台手机做一次确认。

### 无法打开时

- 手机不能打开 `localhost` 或 `127.0.0.1`：那代表手机自己。请用电脑打印的局域网 IP 地址。
- Windows 防火墙弹出 Python 提示时，允许它在你使用的**专用网络**通信。不要直接关闭防火墙。
- 如果没有出现提示但打不开，检查 Windows 的专用网络设置和 Python 防火墙入站权限。
- 不要使用会隔离设备的访客 Wi-Fi。有些公共 Wi-Fi 或手机热点不允许设备互相访问，需要换网络。
- 电脑可能打印多个地址，选择 Wi-Fi 对应的地址。可以用 `ipconfig` 查找 Wi-Fi 网卡的 IPv4。
- 如果 8080 端口被占用，在项目目录运行 `py -3 server.py --port 8081 --open`，手机改用新端口。
- 电脑换网络后 IP 可能会变化，需要重新使用新地址。
- 普通 `start-windows.cmd` 没有登录，只用于自己的可信局域网。跨网络访问使用远程入口，不要直接把此端口映射到公网。

macOS 可以在终端进入项目目录后运行 `python3 server.py --open`。提供了 `start-mac.command` 作为便捷入口；系统若不允许双击，可使用终端命令。

## 界面与订单规则

### 前端

- 三种果汁：Mango、Strawberry、Passion Fruit。
- 珍珠选项：Strawberry、Green Apple、Blueberry、Mango、Watermelon，以及 None（不加珍珠）。后端与销售页显示“无珍珠”。
- 四步创建：口味一 → 口味二 → 珍珠 → Size。两种口味可以相同。
- 选择 Size 只会高亮该杯型，另一杯型变灰；点击“完成创建”才提交。
- 新订单进入队尾，订单编号持续递增。
- “完成订单”只处理当前队首，将其移入销售页。
- 详情里的“删除订单”会从队列移除；可通过撤销恢复。
- 点击删除按钮以外的任意位置可关闭详情。
- “撤销删除/归档”按最近一次操作向前撤销，可以连续撤销。恢复的订单放到队首。
- 撤销“完成订单”时，该订单从销售页移走，对应当前销售数量、金额也同步扣回。

### 后端

- 显示同一份待制作队列，口味全部中文。
- 支持打开详情，点击任意位置关闭。
- 不提供新建、删除、完成或归档操作按钮。
- 中文对应：芒果、草莓、百香果；珍珠为草莓、青苹果、蓝莓、芒果、西瓜。

### 销售信息

- 上方“已归档订单数量”“已归档金额”是**已永久归档的累计值**。
- 列表显示**已完成但尚未永久归档**的订单，口味为中文。
- 下方“当前已完成订单数量”“当前总金额”仅统计当前列表，不包含上方累计值。
- 点击订单可查看详情。删除时有二次确认，并明确提示会永久失去该订单的信息。
- 永久删除后，当前列表数量和当前金额减少，该订单不能再通过前端撤销恢复。
- “永久归档当前列表”确认后清空当前列表，并将数量和金额加到上方累计值。
- 已归档订单数量下面的“详细历史”打开已归档日志，每次永久归档单独保存日期、订单数量和总金额；同一天多次归档会显示多条。
- 日志日期取归档前当前已完成列表第一笔订单的下单日期，按新西兰 Pacific/Auckland 时区计算，不使用归档当天，也不按最早日期重新排序。
- 永久归档的订单不再提供逐单明细或撤销，归档日志、累计数量和金额保留。
- 升级前的旧版只有累计金额和数量，旧归档会作为“升级前归档／日期未知”显示，不编造日期或过去批次数。
- 全部营业完成数 = 上方已归档数 + 当前已完成数；营业完成金额同理。

## 默认价格

菜单单价与销售统计分别记录，全部为纽币：

| Size | 容量 | 页面显示单价 | 销售统计每杯计入 |
| --- | --- | --- | --- |
| 小杯 | 500 mL | NZ$5.99 | NZ$6.00 |
| 大杯 | 700 mL | NZ$6.99 | NZ$7.00 |

价格只取决于 Size，果汁、珍珠不另收费。每笔订单固定为一杯。此版本不处理付款、折扣、额外加料或退款；“完成”代表你手动确认已经完成该订单。

销售总额、永久归档金额，以及删除或撤销时的金额增减，统一按小杯 $6、大杯 $7 计算；下单页面、完成创建按钮和订单详情中的单价仍显示 $5.99 / $6.99。例如一小杯加一大杯，销售统计为 $13.00。

每笔订单分别保存显示单价 `priceCents` 与记账金额 `accountingCents`。若要改价，同时修改前端 `SIZES` 和后端的 `PRICES`（显示价）、`ACCOUNTING_PRICES`（记账价），单位均为分。

旧版记录会自动升级：队列、已完成列表及撤销记录按 Size 补上新的记账价；旧版永久归档金额按每杯补 1 分，转换成 $6 / $7 的统计方式。只升级一次，订单不会清空。

## 数据保存与断线

- **单机模式：** 浏览器本机存储。不同设备各自保存。
- **同步模式：** 电脑上的 `data/orders.sqlite3`。手机刷新、电脑停止后重新启动，都不会自动清空。
- 同步模式只在连接正常、操作获服务器确认后继续操作。断线时会显示提示并暂停创建/完成等按钮，避免出现两台手机各记各的订单。
- 如果请求已发送但回应丢失，会保留该操作编号并重试。服务器识别相同编号，避免重复下单或重复完成。
- 所有金额用整数“分”计算，避免浮点数累计误差。

备份：停止服务器后，复制整个 `data` 文件夹。恢复：停止服务器，使用备份的整个 `data` 文件夹替换后再启动。备份中含有已保存的订单记录，请妥善保管。

明天正式营业前，建议先在另一个解压副本里试单。试好后，用一份全新解压的项目开始营业，这样销售金额和订单编号从空白开始。不要直接删除已存有正式营业数据的目录。

## 项目结构与以后学习的顺序

```text
boba-orders/
  index.html                 页面、样式、交互、单机逻辑
  server.py                  HTTP 接口、业务规则、SQLite 保存
  remote_launcher.py         随机访问码、远程地址与启动器
  start-remote-windows.cmd   Windows 跨网络入口
  prepare-remote.ps1         自动下载官方便携运行组件
  远程使用说明.txt             不同地点使用的详细步骤
  start-windows.cmd          Windows 一键启动
  start-mac.command          macOS 启动入口
  README.md                  使用与排错说明
  tests/test_server.py       订单、金额、历史、升级、重试与并发测试
  timezones/                 内置新西兰时区数据，升级时一并复制
  data/                      第一次启动后自动生成，不随源码分发
  package.json               可选开发预览命令，营业不需要
  .openai/                   开发预览适配，营业不需要
```

前端使用 HTML、CSS、原生 JavaScript；后端使用 Python 标准库 HTTP 服务；数据库使用 SQLite。页面没有 CDN 字体或外部脚本，远程入口使用独立的 Cloudflare 连接程序。之后可以保留这些业务规则，逐步用 Java Spring Boot 和 React + TypeScript 重写。

建议学习顺序：

1. 看一笔订单的数据：口味 ID、珍珠 ID、Size、价格、编号。
2. 看 `index.html` 的 `wizard` 和点击处理：四步创建怎样连接起来。
3. 看 `applyLocal`：队列、完成列表、撤销栈如何变化。
4. 看 `server.py` 的 `apply_action`：服务器如何执行相同业务规则。
5. 看 `Store.command`：SQLite 事务与操作编号如何解决两台手机同时操作、网络重复请求。
6. 看前端的 `sync`、`mutate`、`sendPending`：读取共享数据、保存命令、断线重连。

接口只有两个：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/state` | 读取共享订单和统计 |
| POST | `/api/commands` | 创建、完成、删除、撤销、永久归档 |

写入参数格式：

```json
{
  "requestId": "unique-command-id",
  "action": "create",
  "payload": {
    "flavors": ["mango", "strawberry"],
    "pearl": "blueberry",
    "size": "small"
  }
}
```

POST 请求还需要 `Content-Type: application/json` 和 `X-Boba-Client: 1`，不开放跨域写入。显示价和记账价均由服务器核定，不采用请求中自带的价格。
